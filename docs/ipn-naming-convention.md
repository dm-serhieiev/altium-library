# Правила найменування IPN

**Призначення:** визначити стабільний стандарт Internal Part Number (IPN) для компонентів, що зберігаються в InvenTree та використовуються в Altium Designer, KiCad, BOM, скриптах і процесах закупівлі.

**Сфера застосування:**

- резистори;
- конденсатори;
- індуктивності;
- діоди;
- транзистори;
- інтегральні мікросхеми;
- роз'єми.

---

# 1. Загальні принципи

IPN повинен:

1. Бути коротким і стабільним.
2. Містити лише інформацію, необхідну для розрізнення внутрішніх інженерних компонентів.
3. Не залежати від постачальника.
4. Не залежати від місця зберігання компонента.
5. Не залежати від назв бібліотек Altium або KiCad.
6. Не дублювати параметри, що вже зберігаються окремо в InvenTree, якщо вони не потрібні для забезпечення унікальності IPN.
7. Використовувати лише ASCII-символи.

Рекомендований набір символів:

```text
A-Z
0-9
-
.
%
```

Дефіс `-` використовується як структурний роздільник між полями IPN.

Загальний формат:

```text
<TYPE>-<FIELD1>-<FIELD2>-...
```

---

# 2. Загальні правила форматування

## 2.1. Десятковий роздільник

Для звичайних числових значень використовується крапка `.` як десятковий роздільник.

Приклади:

```text
0.1
0.47
1.25
3.3
```

Наприклад:

```text
3.3V
2.5A
D6.3X10
P2.54
```

Це правило не поширюється на інженерний запис опору, ємності та індуктивності, для яких використовуються окремі правила нижче.

---

## 2.2. Позначення опору

Використовується інженерний запис:

```text
0.1 Ohm   -> 0R1
1 Ohm     -> 1R
4.7 Ohm   -> 4R7
100 Ohm   -> 100R
1 kOhm    -> 1K
4.7 kOhm  -> 4K7
10 kOhm   -> 10K
1 MOhm    -> 1M
2.2 MOhm  -> 2M2
```

Літера одиниці одночасно виконує роль десяткового роздільника.

---

## 2.3. Позначення ємності

Використовуються:

```text
P = pF
N = nF
U = uF
M = mF, лише коли це доцільно
```

Приклади:

```text
22 pF    -> 22P
100 pF   -> 100P
1 nF     -> 1N
4.7 nF   -> 4N7
100 nF   -> 100N
1 uF     -> 1U
4.7 uF   -> 4U7
1000 uF  -> 1000U
```

---

## 2.4. Позначення індуктивності

Використовуються:

```text
N = nH
U = uH
M = mH
```

Приклади:

```text
100 nH -> 100N
1 uH   -> 1U
4.7 uH -> 4U7
10 uH  -> 10U
1 mH   -> 1M
```

---

## 2.5. Позначення напруги

Використовується числове значення із суфіксом `V`.

Приклади:

```text
3.3 V -> 3.3V
5 V   -> 5V
6.3 V -> 6.3V
12 V  -> 12V
50 V  -> 50V
100 V -> 100V
```

---

## 2.6. Позначення струму

Використовуються:

```text
A  = ампер
MA = міліампер
UA = мікроампер
```

Приклади:

```text
100 mA -> 100MA
500 mA -> 500MA
1 A    -> 1A
1.5 A  -> 1.5A
2.5 A  -> 2.5A
```

---

## 2.7. Позначення допуску

Для відсоткових значень використовується знак `%`.

Приклади:

```text
0.1%
0.5%
1%
2%
5%
10%
20%
```

Приклади використання в IPN:

```text
RES-10K-1%-0603
RES-4K7-5%-0805
RSH-10M-1%-2512
```

---

## 2.8. Позначення корпусу

Поле `Package` в IPN повинно використовувати коротке, стабільне та зрозуміле позначення, достатнє для розрізнення внутрішніх інженерних компонентів.

Для стандартних SMD пасивних компонентів використовуються звичні імперські позначення типорозмірів:

```text
0201
0402
0603
0805
1206
1210
1812
2010
2512
```

Для інших категорій компонентів правила запису корпусу визначаються у відповідних розділах цього документа.

---

## 2.9. Позначення механічних розмірів

Механічні розміри в IPN задаються в міліметрах.

Для розділення розмірів використовується велика латинська літера `X`.

Незначущі кінцеві нулі не записуються.

Приклади:

```text
3
3.3
4.3
6.3
10
```

### Прямокутні корпуси

Основний формат:

```text
<LENGTH>X<WIDTH>
```

Приклади:

```text
3X4.3
4X4
6X6
10X10
```

Якщо висота корпусу необхідна для однозначної ідентифікації:

```text
<LENGTH>X<WIDTH>X<HEIGHT>
```

Приклади:

```text
4X4X2
6X6X3
18X7X12
```

Порядок розмірів завжди:

```text
довжина X ширина [X висота]
```

### Циліндричні корпуси

Використовується формат:

```text
D<DIAMETER>X<HEIGHT>
```

Приклади:

```text
D5X11
D6.3X10
D8X12
D10X16
```

Наприклад:

```text
D6.3X10
```

означає:

```text
діаметр корпусу = 6.3 mm
висота корпусу  = 10 mm
```

Якщо для ідентифікації компонента достатньо лише діаметра, допускається скорочений формат:

```text
D12.5
```

### Крок контактів або виводів

Використовується формат:

```text
P<PITCH>
```

Приклади:

```text
P1
P1.27
P2
P2.5
P2.54
P5.08
```

`P` позначає відстань між центрами сусідніх контактів, виводів або терміналів.

---

# 3. Резистори

## 3.1. Постійні резистори

Стандартний формат:

```text
RES-<RESISTANCE>-<TOLERANCE>-<PACKAGE>
```

Приклад:

```text
RES-10K-1%-0603
```

Розшифрування:

```text
RES    постійний резистор
10K    10 kOhm
1%     допуск 1%
0603   типорозмір корпусу
```

Приклади:

```text
RES-0R-1%-0603
RES-0R1-1%-2512
RES-10R-1%-0603
RES-100R-1%-0603
RES-1K-1%-0603
RES-4K7-5%-0805
RES-10K-1%-0603
RES-1M-1%-0603
```

За замовчуванням до IPN не включаються:

- номінальна потужність;
- допустима напруга;
- температурний коефіцієнт;
- технологія виготовлення;
- тип монтажу;
- виробник;
- MPN.

Ці характеристики зберігаються як окремі параметри в InvenTree.

---

## 3.2. Спеціальні типи резисторів

Рекомендовані префікси:

```text
RES   постійний резистор
RSH   вимірювальний / шунтовий резистор
RNET  резисторна збірка / матриця
POT   потенціометр
TRIM  підлаштувальний резистор
NTC   NTC-термістор
PTC   PTC-термістор
```

До IPN включаються лише параметри, необхідні для розрізнення внутрішніх інженерних компонентів.

Приклади:

```text
RSH-10M-1%-2512
NTC-10K-1%-0603
TRIM-10K-SMD
```

Для резисторних збірок, потенціометрів, підлаштувальних резисторів, термісторів та інших нестандартних класів допускається введення додаткових полів, якщо вони необхідні для забезпечення унікальності IPN.

---

# 4. Конденсатори

## 4.1. Керамічні конденсатори

Керамічні конденсатори є основним і найпоширенішим класом конденсаторів, тому тип технології окремо в IPN не зазначається.

Стандартний формат:

```text
CAP-<CAPACITANCE>-<VOLTAGE>-<DIELECTRIC>-<PACKAGE>
```

Приклад:

```text
CAP-100N-50V-X7R-0603
```

Розшифрування:

```text
CAP    керамічний / стандартний конденсатор
100N   100 nF
50V    номінальна напруга
X7R    тип діелектрика
0603   типорозмір корпусу
```

Приклади:

```text
CAP-10P-50V-C0G-0603
CAP-100P-50V-C0G-0603
CAP-1N-50V-C0G-0603
CAP-10N-50V-X7R-0603
CAP-100N-50V-X7R-0603
CAP-1U-25V-X7R-0805
CAP-4U7-16V-X5R-0805
CAP-10U-10V-X5R-0805
```

Для корпусів використовуються стандартні позначення:

```text
0201
0402
0603
0805
1206
1210
1812
```

Допуск за замовчуванням до IPN не включається.

Якщо допуск необхідний для розрізнення невзаємозамінних внутрішніх компонентів, використовується розширений формат:

```text
CAP-<CAPACITANCE>-<VOLTAGE>-<DIELECTRIC>-<TOLERANCE>-<PACKAGE>
```

Приклад:

```text
CAP-10P-50V-C0G-1%-0603
```

Такі параметри, як ESR, температурний діапазон, виробник, MPN та тип монтажу, за замовчуванням зберігаються окремо в InvenTree.

---

## 4.2. Алюмінієві електролітичні конденсатори

Префікс:

```text
CAP-EL
```

Для радіальних THT електролітичних конденсаторів використовується формат:

```text
CAP-EL-<CAPACITANCE>-<VOLTAGE>-D<DIAMETER>X<HEIGHT>-P<PITCH>
```

До IPN включаються:

- діаметр корпусу;
- висота корпусу;
- крок виводів.

Усі геометричні розміри задаються в міліметрах.

Приклади фрагментів корпусу:

```text
D5X11-P2
D6.3X11-P2.5
D8X12-P3.5
D10X16-P5
```

Розшифрування:

```text
D6.3X11-P2.5
│    │    │
│    │    └─ крок виводів = 2.5 mm
│    └────── висота корпусу = 11 mm
└─────────── діаметр корпусу = 6.3 mm
```

Приклади IPN:

```text
CAP-EL-100U-25V-D6.3X11-P2.5
CAP-EL-470U-35V-D10X16-P5
CAP-EL-1000U-16V-D10X20-P5
```

Для SMD алюмінієвих електролітичних конденсаторів, де крок виводів не є доцільним параметром корпусу, використовується формат:

```text
CAP-EL-<CAPACITANCE>-<VOLTAGE>-D<DIAMETER>X<HEIGHT>
```

Приклади:

```text
CAP-EL-100U-25V-D6.3X5.8
CAP-EL-220U-16V-D8X10.2
```

ESR, допустимий струм пульсацій, ресурс, температурний клас, серія виробника та тип монтажу за замовчуванням зберігаються як окремі параметри InvenTree.

---

## 4.3. Полімерні конденсатори

Префікс:

```text
CAP-POL
```

Рекомендований формат:

```text
CAP-POL-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
```

Залежно від конкретного сімейства може використовуватися стандартне позначення корпусу або позначення за геометричними розмірами.

Приклади:

```text
CAP-POL-100U-6.3V-7343
CAP-POL-220U-10V-7343
```

ESR та допустимий струм пульсацій за замовчуванням до IPN не включаються.

---

## 4.4. Танталові конденсатори

Префікс:

```text
CAP-TAN
```

Рекомендований формат:

```text
CAP-TAN-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
```

Для формованих SMD танталових конденсаторів використовуються стандартизовані позначення типорозмірів:

```text
TYPEA
TYPEB
TYPEC
TYPED
TYPEE
```

Приклади:

```text
CAP-TAN-10U-16V-TYPEA
CAP-TAN-22U-10V-TYPEB
CAP-TAN-47U-16V-TYPEC
CAP-TAN-100U-10V-TYPED
```

Геометричні характеристики `TYPEA`, `TYPEB` тощо повинні бути визначені в таблиці відповідності корпусів, що використовується EDA-інтеграцією.

Якщо виробник використовує нестандартне позначення корпусу, яке неможливо однозначно зіставити зі стандартним типом, застосовується загальний формат IPN і окреме зіставлення з EDA footprint або manufacturer-specific package.

ESR, імпульсна напруга, температурний діапазон і серія виробника за замовчуванням до IPN не включаються.

---

## 4.5. Плівкові конденсатори

Префікс:

```text
CAP-FILM
```

Для THT плівкових конденсаторів використовується позначення корпусу за геометричними розмірами.

Рекомендований формат:

```text
CAP-FILM-<CAPACITANCE>-<VOLTAGE>-<LENGTH>X<WIDTH>X<HEIGHT>-P<PITCH>
```

До IPN включаються:

- довжина корпусу;
- ширина корпусу;
- висота корпусу;
- крок виводів.

Усі розміри задаються в міліметрах.

Приклади фрагментів корпусу:

```text
13X5X11-P10
18X7X12-P15
31X14X24-P27.5
```

Розшифрування:

```text
18X7X12-P15
│  │ │    │
│  │ │    └─ крок виводів = 15 mm
│  │ └────── висота корпусу = 12 mm
│  └──────── ширина корпусу = 7 mm
└─────────── довжина корпусу = 18 mm
```

Приклади IPN:

```text
CAP-FILM-100N-250V-13X5X11-P10
CAP-FILM-1U-100V-18X7X12-P15
CAP-FILM-2U2-400V-31X14X24-P27.5
```

Геометрія корпусу включається до IPN, оскільки два плівкові конденсатори з однаковою ємністю, номінальною напругою та кроком виводів можуть мати суттєво різні габарити і не бути механічно взаємозамінними.

Допуск, матеріал діелектрика, `dv/dt`, температурний діапазон, виробник і серія включаються лише тоді, коли вони необхідні для розрізнення невзаємозамінних внутрішніх компонентів.

---

## 4.6. Суперконденсатори

Префікс:

```text
CAP-SC
```

Рекомендований формат:

```text
CAP-SC-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
```

Приклади:

```text
CAP-SC-1F-5.5V-RADIAL
CAP-SC-10F-2.7V-D12.5
```

До позначення корпусу включається лише інформація, необхідна для розрізнення внутрішніх інженерних компонентів і визначення відповідного посадкового місця.

---

# 5. Індуктивності

Корпуси індуктивностей і дроселів стандартизовані менше, ніж корпуси резисторів і конденсаторів. Тому допускаються два способи позначення корпусу.

---

## 5.1. Загальні та силові індуктивності

Префікс:

```text
IND
```

Рекомендований формат:

```text
IND-<INDUCTANCE>-<CURRENT>-<PACKAGE>
```

Приклади:

```text
IND-100N-300MA-0603
IND-1U-1A-0805
IND-4U7-3A-4X4
IND-10U-2A-6X6
IND-47U-1.5A-10X10
```

Струм включається до IPN, оскільки для силових індуктивностей він є одним з основних параметрів вибору.

За замовчуванням до IPN не включаються:

- допуск;
- DC resistance;
- saturation current;
- тип екранування;
- матеріал осердя;
- self-resonant frequency;
- виробник;
- MPN.

Якщо в конкретному інженерному процесі основним параметром є струм насичення, а не номінальний струм, необхідно вибрати один підхід і використовувати його послідовно для всієї відповідної категорії.

---

## 5.2. RF та сигнальні індуктивності

Префікс:

```text
INDRF
```

Рекомендований формат:

```text
INDRF-<INDUCTANCE>-<CURRENT>-<PACKAGE>
```

Приклади:

```text
INDRF-100N-300MA-0603
INDRF-220N-200MA-0402
```

Q factor, test frequency, SRF і DCR за замовчуванням зберігаються окремо в InvenTree.

---

## 5.3. Позначення корпусу за розмірами

Якщо корпус є загальним і може бути однозначно визначений за габаритами, використовується позначення:

```text
<LENGTH>X<WIDTH>
```

Якщо необхідно врахувати висоту:

```text
<LENGTH>X<WIDTH>X<HEIGHT>
```

Усі розміри задаються в міліметрах.

Приклади:

```text
2X1.6
3X3
4X4
5X5
6X6
10X10
4X4X2
6X6X3
```

Приклади IPN:

```text
IND-4U7-3A-4X4
IND-10U-2A-6X6
IND-22U-1.5A-10X10
INDRF-100N-300MA-2X1.6
```

До IPN включаються лише ті розміри, які необхідні для розрізнення механічних варіантів корпусу.

---

## 5.4. Manufacturer-specific package або позначення серії

Якщо механічна конструкція корпусу безпосередньо пов'язана з конкретною серією виробника, використовується усталене позначення корпусу або серії замість штучно створеного геометричного коду.

Приклади:

```text
CDRH4D28
CDRH5D28
SRN4018
SRP5030
XAL5030
LPS4018
```

Приклади IPN:

```text
IND-10U-2A-CDRH5D28
IND-4U7-3.5A-SRP5030
IND-2U2-5A-XAL5030
```

Такий підхід допустимий, оскільки індуктивності з однаковими зовнішніми розмірами можуть суттєво відрізнятися геометрією контактів, посадковим місцем, конструкцією екранування та іншими механічними характеристиками.

---

## 5.5. Вибір способу позначення корпусу

Використовується такий пріоритет:

```text
Універсальний механічно взаємозамінний корпус
    -> позначення за розмірами

Manufacturer-specific або series-specific механіка
    -> позначення корпусу або серії виробника
```

Поле корпусу насамперед повинно допомагати однозначно визначити правильне посадкове місце, а не описувати всі електричні характеристики індуктивності.

---

# 6. Діоди

Для діодів використовується позначення самого компонента або manufacturer part number замість кодування всіх електричних параметрів у IPN.

---

## 6.1. Стандартний формат

```text
DIO-<TYPE>-<PART>
```

Рекомендовані коди типу:

```text
SIG   сигнальний / комутаційний діод
RECT  випрямний діод
SCH   діод Шотткі
ZEN   стабілітрон
TVS   TVS-діод
BRG   діодний міст
ESD   ESD-захисний діод або збірка
```

Приклади:

```text
DIO-SIG-1N4148W
DIO-RECT-1N4007
DIO-SCH-BAT54S
DIO-ZEN-BZT52C5V1
DIO-TVS-SMBJ24A
DIO-ESD-USBLC6-2SC6
```

За замовчуванням до IPN не включаються:

- допустима напруга;
- допустимий струм;
- forward voltage;
- напруга стабілізації;
- потужність;
- reverse recovery time;
- leakage current;
- корпус.

Ці параметри зберігаються окремо в InvenTree.

---

## 6.2. Суфікси виробника

Використовується та частина manufacturer ordering code, яка визначає реальний електричний і механічний компонент.

Суфікси постачання, які позначають лише:

```text
Tape-and-Reel
Cut Tape
Tray
Bulk
```

не повинні створювати окремий IPN, якщо InvenTree навмисно не розглядає такі варіанти як різні внутрішні інженерні компоненти.

---

# 7. Транзистори

Для транзисторів використовується той самий принцип, що і для діодів: IPN базується на позначенні компонента, а не на кодуванні всіх його електричних параметрів.


## 7.4. IGBT

---

## 8.2. Правило для ordering code

Manufacturer ordering code використовується лише в тій мірі, яка необхідна для ідентифікації реального внутрішнього інженерного компонента.

Суфікси, що визначають лише тип упаковки або постачання, за замовчуванням не створюють окремий IPN.

Наприклад:

```text
AD8606ARMZ
AD8606ARMZ-REEL
```

можуть відповідати одному InvenTree Part, якщо їх електрична та механічна ідентичність однакова.

Точний manufacturer MPN у будь-якому випадку зберігається в сутності Manufacturer Part.

---

## 8.3. Правило корпусу

Корпус зазвичай не додається до IPN окремим полем:

```text
IC-MCU-STM32H723VGT6
```

Оскільки корпус часто вже закодований у manufacturer ordering code і додатково зберігається в параметрі `Package` в InvenTree.

Правила форматування числових значень цього документа не застосовуються всередині оригінального manufacturer ordering code.

Наприклад:

```text
LM2937IMP-5P0
```

залишається без змін, якщо `5P0` є частиною офіційного MPN виробника.

# 9. Роз'єми

Для роз'ємів використовуються дві стратегії формування IPN:

1. Generic connector — внутрішній компонент визначається переважно геометрією та функцією.
2. Manufacturer-specific connector — критичною є сумісність серії або конкретний MPN.

---

## 9.1. Generic connectors

Формат:

```text
CON-<TYPE>-<CONTACTS>-<PITCH>-<MOUNT>-<ORIENTATION>
```

Рекомендовані коди типу:

```text
HDR     pin header
SOCK    socket header
TERM    terminal block
IDC     IDC connector
FFC     FFC / FPC connector
USB     USB connector
PWR     power connector
AUDIO   audio connector
RF      RF connector
CARD    card / memory socket
BTB     board-to-board
WTB     wire-to-board
```

Кількість і розташування контактів:

```text
1X02
1X06
2X05
2X10
```

Позначення `X` у цьому випадку описує структуру масиву контактів і не є позначенням механічних розмірів.

Крок:

```text
P1
P1.27
P2
P2.54
P5.08
```

Тип монтажу:

```text
THT
SMD
PRESSFIT
```

Орієнтація:

```text
VERT
RA
```

Приклади:

```text
CON-HDR-1X06-P2.54-THT-VERT
CON-HDR-2X05-P2.54-THT-VERT
CON-SOCK-2X05-P2.54-THT-VERT
CON-TERM-1X03-P5.08-THT-VERT
CON-USB-C-24P-SMD-RA
```

---

## 9.2. Manufacturer-specific connectors

Формат:

```text
CON-<FAMILY_OR_MANUFACTURER>-<PART>
```

Приклади:

```text
CON-JST-BM04B-PH-K-S
CON-JST-S4B-PH-K-S
CON-MOLEX-53398-0471
CON-HIROSE-DF13-6P-1P25H
CON-GCT-USB4105-GF-A
```

Оригінальне manufacturer part number або позначення серії зберігається без зміни внутрішнього формату.

Цей формат застосовується, коли мають значення:

- mating compatibility;
- keying;
- locking;
- точна механічна геометрія;
- конкретне посадкове місце.

Кількість контактів, крок, тип контакту, орієнтація, тип монтажу, допустимий струм, допустима напруга та mating series при цьому також повинні зберігатися окремими параметрами в InvenTree.

# 11. Правила унікальності

IPN ідентифікує **внутрішній інженерний компонент**, а не окрему позицію закупівлі.

Перед створенням нового IPN необхідно:

1. Перевірити наявність еквівалентного внутрішнього Part.
2. Порівняти параметри, що визначають взаємозамінність.
3. Додавати нове поле до IPN лише тоді, коли воно необхідне для розрізнення двох допустимих внутрішніх Parts.
4. Не додавати параметри лише тому, що вони доступні в datasheet.

Приклад:

```text
InvenTree Part:
RES-10K-1%-0603

Manufacturer Parts:
- Yageo RC0603FR-0710KL
- Vishay CRCW060310K0FKEA
- Panasonic ERJ-3EKF1002V
```

Якщо ці компоненти визнані взаємозамінними, вони використовують один IPN.

Аналогічно:

```text
CAP-100N-50V-X7R-0603
```

може містити декілька затверджених Manufacturer Parts.

---

# 12. Зв'язок із Manufacturer Parts

IPN описує внутрішню інженерну ідентичність компонента.

Manufacturer Part містить точного виробника та MPN.

Окремі IPN не створюються лише через відмінності в:

- виробнику;
- постачальнику;
- supplier SKU;
- кількості в упаковці;
- Tape-and-Reel / Cut Tape;
- іншому способі пакування.

Винятком є випадок, коли існує реальна інженерна або виробнича причина розглядати такі компоненти як різні внутрішні Parts.

---

# 13. Зв'язок з EDA-ідентифікаторами

IPN не повинен містити:

- назву бібліотеки Altium;
- назву Altium Symbol;
- назву Altium Footprint;
- назву бібліотеки KiCad;
- назву KiCad Symbol;
- назву KiCad Footprint.

Наприклад:

```text
IPN:
RES-10K-1%-0603

Altium Symbol:
Resistor

Altium Footprint:
RES_0603_H0.55

KiCad Symbol:
Device:R

KiCad Footprint:
Resistor_SMD:R_0603_1608Metric
```

Ці ідентифікатори є незалежними від IPN та можуть змінюватися без зміни самого IPN.

Поле `Package` також не є заміною поля `Footprint`.

Наприклад:

```text
Package:
0603

Footprint:
RES_0603_H0.55
```

Різні компоненти з однаковим `Package` можуть використовувати різні посадкові місця, якщо цього потребує їх механічна реалізація.

---

# 14. Правила внесення змін

Після використання IPN у випущених BOM або виробничих записах:

1. IPN не перейменовується лише з косметичних причин.
2. Значення вже існуючого IPN не змінюється.
3. Якщо змінюється інженерна ідентичність компонента, створюється новий InvenTree Part.
4. Альтернативні затверджені компоненти виробників додаються як Manufacturer Parts, а не як нові IPN.
5. Нові правила найменування застосовуються до нових Parts, якщо не виконується контрольована міграція існуючих IPN.
