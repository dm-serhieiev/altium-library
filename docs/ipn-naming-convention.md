# Правила найменування IPN

Це основна конвенція Internal Part Number для бібліотеки. Вона визначає ідентичність інженерного компонента та формати нових IPN. [Категорії](inventree-category-structure.md) і [назви моделей Altium](library-convention.md) мають окремі правила. Приклади нижче ілюструють позначення; вони не підтверджують наявність Part на сервері, конкретного виробу в запасах або його взаємозамінність.

## Ідентичність і стабільність

IPN ідентифікує внутрішній інженерний Part, а не складський екземпляр, артикул постачальника чи довільний рядок специфікації. Один Part може мати кілька схвалених Manufacturer Parts і Supplier Parts. Кількість Stock Items не змінює його IPN.

Компоненти з однаковими номіналом і корпусом не обов'язково взаємозамінні. Перевіряють електричні межі й умови, допуски, температурні характеристики, механіку, контакти/полярність, символ, посадкове місце та вимоги конкретного застосування. Якщо існуючий формат не розрізняє невзаємозамінні деталі, погоджують уточнення формату до створення нового IPN; не об'єднують деталі лише через збіг короткого коду.

Використаний IPN має залишатися стабільним. Косметичне вдосконалення конвенції не є підставою для автоматичного перейменування. Зміна інженерної ідентичності потребує окремого Part/IPN; виправлення помилкового коду — контрольованої міграції з перевіркою BOM, схем, PCB та посилань. `inventree-sync` переносить `Part.IPN` як є, перевіряє його наявність/унікальність і не генерує, не розбирає та не виправляє його.

## Контексти запису даних

| Поле | Призначення | Приклад для 4,7 nF |
|---|---|---|
| IPN | Стабільний внутрішній ідентифікатор | `CAP-4N7-50V-X7R-0603` |
| Value | Текст на схемі; регістр має значення | `4n7` |
| Capacitance.data / units | Значення електричного параметра та одиниці | `4.7n` / `F` |
| Manufacturer Part / MPN | Точний код виробника для схваленого виробу | З документації виробника, без переформатування |

Великі літери сегментів IPN — локальна конвенція ідентифікатора. Вони не змінюють регістр фізичних SI-префіксів у Value або числових параметрах: IPN `100N` відповідає відображенню `100n`, а не `100N`; IPN `4U7` — `4u7`. Для текстового Value використовуйте усталене позначення схеми, наприклад `10k` для 10 kΩ. `Value` має порожні metadata units.

Для параметра з одиницями експортер розпізнає скаляр `4.7n`, але не перетворює `4n7` на число. Він додає одиниці без перерахунку; правила описані в [технічній документації](../tools/inventree-sync/README.md#text-and-units). Роздільники та регістр MPN визначає виробник, а не ці правила інженерних числових сегментів.

## Загальне форматування

Для створених за цією конвенцією загальних IPN використовуються великі латинські літери, цифри, дефіс, крапка та `%`: `A–Z`, `0–9`, `-`, `.`, `%`. Пробіли, кирилиця і десяткова кома не використовуються. Дефіс відокремлює структурні поля:

```text
PREFIX-FIELD-FIELD-...
```

У форматах із кінцевим `<PART>` внутрішні дефіси цього поля є частиною позначення виробника. Наприклад, `DIO-ESD-USBLC6-2SC6` не має нового числового поля після `USBLC6`. Не застосовуйте розбиття за кожним дефісом як універсальний парсер IPN.

У загальних числових полях десятковий роздільник — крапка: `3.3V`, `2.5A`, `D6.3X10`, `P2.54`. Літерно-десяткові коди R/C/L нижче є окремим усталеним форматом. Не замінюйте крапку літерою P у числових полях.

Точний MPN зберігається в Manufacturer Part, включно з регістром і пунктуацією. В IPN на його основі залишають частину ordering code, що визначає електричний/механічний виріб. Не змінюйте символи всередині цієї частини заради загального алфавіту. Якщо значущий код містить символи поза ним, потрібне явне погодження винятку; автоматичної заміни `/`, `+` чи інших знаків ця конвенція не задає. Уже використані IPN не перейменовують автоматично.

### Опір

R позначає оми, K — кілооми, M — мегаоми; літера може замінювати десятковий роздільник.

| Опір | Сегмент IPN |
|---|---|
| 10 mΩ | `0R01` |
| 0,1 Ω | `0R1` |
| 1 Ω | `1R` |
| 4,7 Ω | `4R7` |
| 100 Ω | `100R` |
| 1 kΩ | `1K` |
| 4,7 kΩ | `4K7` |
| 10 kΩ | `10K` |
| 1 MΩ | `1M` |
| 2,2 MΩ | `2M2` |

**`10M` означає 10 MΩ, а не 10 mΩ.** Для ілюстрації шунта 10 mΩ використовується `RSH-0R01-1%-2512`. Це виправлення прикладу, не команда перейменувати існуючі Parts.

### Ємність та індуктивність

| Величина | Літери у сегменті IPN | Приклади |
|---|---|---|
| Ємність | P = pF, N = nF, U = µF, M = mF; F = F | `22P`, `100P`, `1N`, `4N7`, `100N`, `1U`, `4U7`, `1000U`, `1F` |
| Індуктивність | N = nH, U = µH, M = mH | `100N`, `1U`, `4U7`, `10U`, `1M`, `2M2` |

Контекст префікса IPN визначає фізичну величину: `IND-100N-...` та `CAP-100N-...` мають різні одиниці. Позначення `1000U` залишається допустимим; не перейменовуйте на `1M` лише через еквівалентність значень. Верхній регістр IPN не переноситься в SI-текст Value.

### Напруга, струм, допуск

Напруга: число з крапкою за потреби та V, наприклад `3.3V`, `6.3V`, `25V`, `50V`, `250V`.

Струм у IPN: A, MA, UA, наприклад `2A`, `1.5A`, `300MA`, `100UA`. Тут MA означає міліампери **лише за конвенцією сегмента IPN**. У фізичному тексті параметра це `mA`, а не `MA` (мегаампери); µA/uA також не замінюють на UA поза IPN.

Допуск: число й `%`, наприклад `0.1%`, `0.5%`, `1%`, `5%`, `10%`, `20%`. Не використовуйте `1PCT` чи `1P` як альтернативу. Асиметричний допуск потребує окремо погодженого формату, а не довільної підстановки.

### Корпуси та механічні розміри

Для чип-резисторів і відповідних конденсаторів використовуються дюймові коди `0201`, `0402`, `0603`, `0805`, `1206`, `1210`, `1812`, `2010`, `2512`, зі збереженням початкового нуля. Це не універсальна система для всіх корпусів: наприклад, `7343` у полімерного конденсатора — інша система позначення.

Розміри задають у міліметрах, із крапкою, великим X та без зайвих кінцевих нулів у нових геометричних полях IPN:

| Форма | Формат | Приклади |
|---|---|---|
| Прямокутна | `<LENGTH>X<WIDTH>` | `4X4`, `2X1.6` |
| З висотою | `<LENGTH>X<WIDTH>X<HEIGHT>` | `6X6X3`, `18X7X12` |
| Циліндрична | `D<DIAMETER>X<HEIGHT>` | `D6.3X11`, `D10X16` |
| Лише діаметр, коли достатньо | `D<DIAMETER>` | `D12.5` |
| Крок | `P<PITCH>` | `P2.5`, `P2.54`, `P5.08`, `P27.5` |

Контактний масив `2X05` у роз'ємі означає два ряди по п'ять контактів, а не габарит. Включайте достатньо механічних ознак для розрізнення, але не намагайтеся вмістити повне креслення в IPN. Окремі правила назв footprint, зокрема H0.55, наведені в [конвенції моделей](library-convention.md#footprint-names); не переформатовуйте їх як сегменти IPN.

## Резистори

### Постійні резистори

```text
RES-<RESISTANCE>-<TOLERANCE>-<PACKAGE>
```

Приклади: `RES-10K-1%-0603`, `RES-4K7-1%-0805`, `RES-100R-5%-1206`, `RES-0R1-1%-2512`.

Потужність, температурний коефіцієнт, технологія, робоча напруга й інші характеристики зберігаються окремо. Якщо вони розділяють невзаємозамінні інженерні Parts із однаковим базовим кодом, потрібне погоджене уточнення IPN. Виробник/MPN обліковуються через Manufacturer Parts, а не обов'язкові однойменні параметри.

### Спеціальні резистори

| Префікс | Родина |
|---|---|
| RSH | Шунтові та вимірювальні резистори |
| RNET | Резисторні збірки |
| POT | Потенціометри |
| TRIM | Підлаштувальні резистори |
| NTC | NTC-термістори |
| PTC | PTC-термістори |

Однозначні ілюстрації: `RSH-0R01-1%-2512`, `NTC-10K-1%-0603`. У термістора опір має визначену опорну температуру; його короткий код не замінює перевірку характеристики.

Префікси не визначають повної граматики для кожної спеціальної родини. Для RNET/POT/TRIM треба погодити поля топології, кількості елементів, механіки й інших відмінностей, якщо вони потрібні. Загальний запис лише з `SMD` не визначає корпус підлаштувального резистора. Не використовуйте його як доказ достатньої ідентичності.

## Конденсатори

### Керамічні

```text
CAP-<CAPACITANCE>-<VOLTAGE>-<DIELECTRIC>-<PACKAGE>
CAP-<CAPACITANCE>-<VOLTAGE>-<DIELECTRIC>-<TOLERANCE>-<PACKAGE>
```

Другий формат застосовується, коли допуск потрібний для розрізнення внутрішніх Parts. Діелектрик важливий для інженерної ідентичності. Використовуйте узгоджений код, наприклад C0G, X5R або X7R; це не довільне переписування назви матеріалу.

Приклади: `CAP-100N-50V-X7R-0603`, `CAP-4U7-16V-X5R-0805`, `CAP-10P-50V-C0G-1%-0603`. Інші електричні характеристики зберігаються окремо та враховуються під час схвалення замін.

### Алюмінієві електролітичні

Для радіальних вивідних корпусів:

```text
CAP-EL-<CAPACITANCE>-<VOLTAGE>-D<DIAMETER>X<HEIGHT>-P<PITCH>
```

Приклади: `CAP-EL-100U-25V-D6.3X11-P2.5`, `CAP-EL-470U-35V-D10X16-P5`.

Для SMD-варіанта за чинною конвенцією:

```text
CAP-EL-<CAPACITANCE>-<VOLTAGE>-D<DIAMETER>X<HEIGHT>
```

Приклад: `CAP-EL-100U-25V-D6.3X5.8`. Перевірте також геометрію основи/контактів, ESR, допустимий пульсаційний струм і ресурс; самі діаметр/висота не доводять сумісності.

### Полімерні та танталові

```text
CAP-POL-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
CAP-TAN-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
```

Приклади: `CAP-POL-100U-6.3V-7343`, `CAP-TAN-10U-16V-TYPEA`, `CAP-TAN-22U-10V-TYPEB`, `CAP-TAN-47U-16V-TYPEC`, `CAP-TAN-100U-10V-TYPED`. Для танталових корпусів конвенція використовує TYPEA–TYPEE.

Код типу звіряють із кресленням виробника, включно з висотою та виводами; не припускайте універсальної геометрії лише за літерою. `Package` не перетворюється синхронізатором на модель. Конкретне посадкове місце задається явним `Altium Footprint`; автоматичної таблиці Package → footprint немає.

### Плівкові

```text
CAP-FILM-<CAPACITANCE>-<VOLTAGE>-<LENGTH>X<WIDTH>X<HEIGHT>-P<PITCH>
```

Приклади: `CAP-FILM-100N-250V-13X5X11-P10`, `CAP-FILM-1U-100V-18X7X12-P15`, `CAP-FILM-2U2-400V-31X14X24-P27.5`.

Однакові ємність/напруга/крок не гарантують однакових габаритів, тому геометрія включена у формат. Допуск, матеріал, dv/dt, температурні/спеціальні характеристики можуть вимагати погодженого уточнення, якщо визначають окрему інженерну ідентичність.

### Суперконденсатори

```text
CAP-SC-<CAPACITANCE>-<VOLTAGE>-<PACKAGE>
```

Ілюстрації форми: `CAP-SC-1F-5.5V-RADIAL`, `CAP-SC-10F-2.7V-D12.5`. RADIAL або сам діаметр недостатні, якщо існує кілька несумісних варіантів. Для реального нового Part необхідно уточнити механіку за загальними правилами; ці приклади не запроваджують універсальний footprint.

## Індуктивності

```text
IND-<INDUCTANCE>-<CURRENT>-<PACKAGE>
INDRF-<INDUCTANCE>-<CURRENT>-<PACKAGE>
```

IND — загальні/силові, INDRF — RF та сигнальні. Приклади: `IND-100N-300MA-0603`, `IND-4U7-3A-4X4`, `IND-10U-2A-6X6`, `INDRF-220N-200MA-0402`.

За замовчуванням CURRENT означає номінальний струм; струм насичення, DCR, допуск, Q, частота вимірювання, SRF, екранування й матеріал осердя зберігаються окремо. Раніше дозволено вибирати струм насичення як основний для конкретної категорії за послідовного застосування. Цей виняток збережено, але конкретна категорія/зміст CURRENT мають бути явно погоджені: не змішуйте номінальний струм і струм насичення та не переосмислюйте існуючі IPN.

Універсальну механіку можна позначати розмірами `4X4`, `6X6`, за потреби `4X4X2`. Для геометрії, залежної від виробника/серії, допускається усталений код: `CDRH4D28`, `CDRH5D28`, `SRN4018`, `SRP5030`, `XAL5030`, `LPS4018`. Приклад синтаксису — `IND-10U-2A-CDRH5D28`; це не перевірена специфікація конкретного виробу.

Однакові зовнішні розміри не гарантують однакової контактної геометрії. Пріоритет: загальне механічно взаємозамінне виконання → розміри; виконання конкретної серії → код корпусу/серії. Явний Altium Footprint обирається незалежно.

## Діоди

```text
DIO-<TYPE>-<PART>
```

| TYPE | Родина | Приклад |
|---|---|---|
| SIG | Сигнальні / комутаційні | `DIO-SIG-1N4148W` |
| RECT | Випрямні | `DIO-RECT-1N4007` |
| SCH | Шотткі | `DIO-SCH-BAT54S` |
| ZEN | Стабілітрони | `DIO-ZEN-BZT52C5V1` |
| TVS | TVS-захист | `DIO-TVS-SMBJ24A` |
| BRG | Випрямні мости | Формат `DIO-BRG-<PART>` |
| ESD | ESD-захист / збірки | `DIO-ESD-USBLC6-2SC6` |

PART — позначення, що визначає реальний електричний і механічний виріб. Напруги, струми, падіння напруги, потужність, час відновлення, витік і корпус за замовчуванням не кодують повторно; їх перевіряють за даними Part/Manufacturer Part.

## Транзистори

| Родина | Формат | Приклади |
|---|---|---|
| MOSFET | `MOS-<CHANNEL>-<PART>`, CHANNEL = N або P | `MOS-N-AO3400A`, `MOS-P-AO3401A`, `MOS-N-IRLZ44N` |
| BJT | `BJT-<POLARITY>-<PART>`, POLARITY = NPN або PNP | `BJT-NPN-BC847B`, `BJT-PNP-BC857B`, `BJT-NPN-MMBT3904` |
| JFET | `JFET-<CHANNEL>-<PART>`, CHANNEL = N або P | `JFET-N-J113`, `JFET-N-MMBFJ310` |
| IGBT | `IGBT-<PART>` | `IGBT-IKW40N120H3` |

Напруги, струми, RDS(on), коефіцієнт підсилення, заряд затвора, поріг, потужність та корпус зберігають окремо там, де ці характеристики застосовні. MOSFET-поля не поширюються на всі транзистори. Складені/комплементарні прилади можуть вимагати окремого погодженого формату; не примушуйте їх до одиничного N/P або NPN/PNP.

## Тиристори та симістори

```text
SCR-<PART>
TRIAC-<PART>
```

Приклад симістора: `TRIAC-BTA16-600B`. Скорочена назва сімейства без значущого варіанта не є достатнім PART. Ці префікси зберігаються; у [рекомендованому дереві](inventree-category-structure.md#thyristors-and-triacs--тиристори-та-симістори) це окрема родина Thyristors and Triacs, а не підкатегорія звичайних транзисторів.

## Інтегральні мікросхеми

```text
IC-<FUNCTION>-<PART>
```

FUNCTION — основна інженерна функція, не корпус і не виробник.

| Коди | Функції |
|---|---|
| MCU, MPU, FPGA, CPLD, MEM, LOG | Мікроконтролери, процесори, програмована логіка, пам'ять, цифрова логіка |
| OPA, CMP, INA, ASW | Операційні підсилювачі, компаратори, вимірювальні підсилювачі, аналогові ключі |
| ADC, DAC, CODEC, AFE | Перетворювачі даних, кодеки, аналогові інтерфейсні вузли |
| LDO, DCDC, REF, PMIC, LSW, EFUSE, HSS | Стабілізатори, перетворювачі, опорні джерела, керування живленням, ключі, електронні запобіжники |
| RS232, RS485, CAN, LIN, USB, ETH, IOX, BRG | Інтерфейси, розширювачі вводу/виводу, інтерфейсні мости |
| CLK, GDRV, MDRV, LEDDRV, RF, SPEC | Тактування, драйвери затворів/двигунів/LED, RF та спеціальні функції |

Приклади: `IC-MCU-STM32H723VGT6`, `IC-DAC-PCM1796D`, `IC-OPA-AD8606ARMZ`, `IC-REF-REF5050AID`, `IC-DCDC-AOZ1282CI`, `IC-GDRV-UCC27211D`, `IC-MEM-W25Q128JVSIQ`.

PART зберігає значущі суфікси корпусу, виконання, температури та електричних опцій. Не додавайте ще один корпус у кінець, якщо ordering code вже однозначно його визначає. Сам код сімейства, що охоплює кілька корпусів/виконань, недостатній.

Приклад числової помилки виправлено: базове позначення `LM2937IMP-5.0` містить крапку, не `5P0`; відповідний ілюстративний IPN — `IC-LDO-LM2937IMP-5.0`. Точний замовний код `LM2937IMP-5.0/NOPB` зберігають у Manufacturer Part. Джерело: [TI, LM2937IMP-5.0/NOPB](https://www.ti.com/product/LM2937/part-details/LM2937IMP-5.0/NOPB). Вибір суфіксів для внутрішньої ідентичності має бути схвалений; це не загальне правило видаляти всі суфікси після `/`.

### Варіанти постачання та MPN

Tape-and-Reel, Cut Tape, Tray або Bulk самі по собі не створюють нової електричної/механічної ідентичності. Не створюйте різних IPN лише через упаковку, якщо інженерний процес явно не визначає такі внутрішні варіанти окремо. Зберігайте точні замовні MPN і дані постачання у відповідних сутностях InvenTree.

Не видаляйте літеру R, суфікс -REEL або будь-який інший суфікс універсальним правилом: значення коду перевіряють у виробника. Відмінності, що змінюють корпус, температурний клас чи електричний варіант, залишаються значущими. Цей принцип також застосовується до діодів і транзисторів.

## Роз'єми

### Загальні механічно взаємозамінні виконання

```text
CON-<TYPE>-<CONTACTS>-<PITCH>-<MOUNT>-<ORIENTATION>
```

| Поле | Значення / приклади |
|---|---|
| TYPE | HDR, SOCK, TERM, IDC, FFC, USB, PWR, AUDIO, RF, CARD, BTB, WTB |
| CONTACTS | `1X02`, `1X06`, `2X05`, `2X10`: ряди × контакти у ряду |
| PITCH | `P1.25`, `P2`, `P2.54`, `P5.08`: крок у мм |
| MOUNT | THT, SMD, PRESSFIT |
| ORIENTATION | VERT, RA |

Приклади: `CON-HDR-1X06-P2.54-THT-VERT`, `CON-HDR-2X05-P2.54-THT-VERT`, `CON-SOCK-2X05-P2.54-THT-VERT`, `CON-TERM-1X03-P5.08-THT-VERT`.

Типи USB/RF/CARD тощо часто потребують конкретної механіки, яку ця загальна формула не описує. Короткий запис USB без PITCH і з іншою структурою полів не є прикладом цього формату. До погодження окремого загального формату використовуйте нижче наведену ідентифікацію за виробником/серією, якщо вона однозначно визначає виріб. Не вигадуйте крок або геометрію для заповнення шаблону.

PRESSFIT є чинним кодом IPN, але загальний список Mounting Type у [категоріях](inventree-category-structure.md#питання-для-окремого-узгодження) поки містить лише SMD/THT; розширення потребує окремого рішення.

### Виконання конкретного виробника або серії

```text
CON-<FAMILY_OR_MANUFACTURER>-<PART>
```

Приклади: `CON-JST-BM04B-PH-K-S`, `CON-JST-S4B-PH-K-S`, `CON-MOLEX-53398-0471`, `CON-HIROSE-DF13-6P-1P25H`, `CON-GCT-USB4105-GF-A`.

Внутрішня пунктуація PART зберігається. Наприклад, `1P25` у коді Hirose — частина позначення виробника; це не дозвіл записувати загальне поле PITCH як `P1P25` замість `P1.25`. Серійне виконання використовують, коли однакові число контактів/крок/орієнтація не гарантують сумісності геометрії чи сполучення.

## Зв'язок із бібліотеками та даними InvenTree

IPN не є назвою символу, footprint або файлу бібліотеки. Один символ/footprint може обслуговувати багато різних Parts. Наприклад:

```text
IPN = RES-10K-1%-0603
Value = 10k
Package = 0603
Altium Symbol = Passives:Resistor
Altium Footprint = Resistors:RES_0603_H0.55
```

Модель задається явно; синхронізатор не отримує її з IPN або Package. Електричні характеристики залишаються в параметрах Part, точні MPN — у Manufacturer Parts, комерційні пропозиції — у Supplier Parts. Схвалення кількох виробників для одного IPN є інженерним рішенням, а не наслідком збігу назви.

## Питання для окремого узгодження

- Повні формати RNET/POT/TRIM, складених транзисторів та інших родин без визначеної граматики не слід вигадувати під час синхронізації. Погоджуйте поля перед створенням нових IPN.
- Виняток CURRENT для струму насичення індуктивностей потребує явного рішення для конкретної категорії; пропозиція для подальшого узгодження — закріпити номінальний Current Rating для нових загальних форматів та описати наявні винятки окремо.
- Значущі MPN-символи поза загальним алфавітом потребують погодженого винятку, без автоматичної заміни. У Manufacturer Part точний MPN зберігається завжди.
- Узагальнені корпуси RADIAL/D12.5 та короткі серійні назви достатні лише там, де вони справді розрізняють механіку. Уточнення вже використаного IPN можливе лише як контрольована міграція.
- Виправлення прикладів у цьому документі не змінює сервер, існуючі BOM, SQLite або бібліотеки Altium.
