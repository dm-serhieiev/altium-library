# Синхронізація бібліотеки з InvenTree

`inventree-sync.exe` завантажує компоненти з InvenTree та оновлює SQLite-базу для Altium DbLib. Для запуску у Windows не потрібні Python, інсталятор або права адміністратора. Використовуйте executable разом із папками бібліотеки цього репозиторію.

## Налаштування

Поруч із `inventree-sync.exe` має бути локальний `config.toml`. Якщо його немає, вручну скопіюйте [config.example.toml](config.example.toml) у `config.toml` і вкажіть адресу InvenTree та шлях кореневої категорії. Існуючий файл не перезаписуйте. Програма не створює конфігурацію та не читає приклад автоматично.

Параметри `[sync]` задають вихідну базу й розташування DbLib, `[libraries]` — папки символів і посадкових місць. Відносні шляхи рахуються від `tools/config.toml`: наприклад, `../database/components.sqlite`. Підтримуються `.sqlite` та `.sqlite3`.

За замовчуванням програма один раз запитує Username і прихований Password. Облікові дані не зберігаються. Підтримуються HTTP та HTTPS; перевірка TLS-сертифікатів залишається увімкненою. Локальний `config.toml` не додавайте в Git.

## Запуск

Перед синхронізацією закрийте Altium та інші програми, що працюють із базою. Двічі клацніть `inventree-sync.exe`: виконається `sync`, а після завершення або помилки вікно чекатиме Enter.

Або виконайте з кореня репозиторію в PowerShell:

```powershell
.\tools\inventree-sync.exe
.\tools\inventree-sync.exe sync
.\tools\inventree-sync.exe validate
.\tools\inventree-sync.exe inspect
.\tools\inventree-sync.exe --help
```

У вже відкритому терміналі додаткової паузи немає. `inspect` показує зведення вихідних даних. `validate` перевіряє повний експорт у пам'яті. Обидві команди залишають базу незмінною. `sync` публікує нову базу лише після перевірки всіх даних.

## Робота без сервера та Git

Репозиторій містить перевірений snapshot [database/components.sqlite](../database/components.sqlite). Altium може використовувати його через SQLite ODBC без доступу до InvenTree; локальне підключення налаштовується командою нижче. Це остання збережена копія, яка може відставати від сервера. Невдалий sync не замінює її; повторіть синхронізацію після відновлення доступу.

Виправляйте компоненти в InvenTree. Ручні зміни бази наступний sync замінить. Після успішного sync перевірте дані й роботу Altium, закрийте споживачів бази та переконайтеся, що вона не має незавершених транзакцій. Оновлений snapshot можна зберегти вручну:

```powershell
git status --short
git add database/components.sqlite
git commit -m "Update component snapshot"
```

Програма сама не створює Git-комітів і не виконує push. `.DbLib`, `.SchLib` і `.PcbLib` автоматично не редагуються. У DbLib вручну використовуйте `IPN` як ключ, налаштуйте технічні model fields і звичайний параметр `InvenTree PK` → `InvenTree PK`. Comment символу використовує `=Value`.

## Налаштування ODBC для Altium

`inventree-sync.exe` оновлює базу компонентів. Окремий [setup-odbc.ps1](setup-odbc.ps1) налаштовує Windows, щоб Altium міг її читати. Ці операції незалежні; setup не потребує Python, доступу до InvenTree або інтернету та не змінює базу чи бібліотеки.

Потрібен уже встановлений **64-бітний SQLite3 ODBC Driver** (`sqlite3odbc.dll`). Якщо його немає, встановіть відповідний Windows x64 пакет `sqliteodbc_w64.exe` з [сайту SQLite ODBC](https://www.ch-werner.de/sqliteodbc/). Setup показує знайдені SQLite-драйвери, але нічого не завантажує й не інсталює.

Закрийте Altium та інші споживачі бази. З кореня репозиторію виконайте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\setup-odbc.ps1
```

Скрипт сам визначає абсолютний шлях до `database/components.sqlite` від власного розташування. Його можна запускати з іншої робочої папки, вказавши повний шлях до скрипту. Підтримуються пробіли та Unicode. Використовуйте 64-бітний Windows PowerShell 5.1; звичайне налаштування User DSN не потребує адміністратора.

Зазвичай достатньо одного запуску для поточного користувача Windows на кожному комп'ютері. Після переміщення репозиторію запустіть setup знову: він оновить **64-бітний User DSN `AltiumComponents`**. Якщо шлях уже правильний, параметри не змінюються. Один DSN відповідає одному активному розташуванню бібліотеки; запуск з іншого клону перенаправить його на цей клон.

Перевірка без змін:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\setup-odbc.ps1 -CheckOnly
```

Після повідомлення `Altium database connection is ready.` відкрийте `database/Components.DbLib` в Altium і виконайте **Connect**. Перевірте видимість таблиць, пошук IPN, розміщення символу та footprint. Connection string уже використовує `DSN=AltiumComponents`; редагувати машинозалежний шлях у DbLib на інших комп'ютерах не потрібно.

Якщо snapshot відсутній або пошкоджений, спочатку відновіть його чи виконайте успішний sync. Однойменний System DSN або User DSN з іншим драйвером setup не перезаписує: явно розв'яжіть конфлікт у **ODBC Data Sources (64-bit)**. Після невдалої перевірки нового шляху скрипт намагається відновити попереднє налаштування й повідомляє про незавершений rollback. Через обмеження драйвера шлях репозиторію не може містити `;`; це перевіряється до зміни DSN. Додаткові DSN-опції, які запускають розширення, пишуть trace або змінюють journal mode, також потребують ручного розв'язання.

Необов'язковий `-DriverName 'точна назва'` вибирає лише встановлений 64-бітний запис того самого драйвера `sqlite3odbc.dll`; автоматичної заміни драйверів немає. Коди setup: `0` — перевірка успішна, `1` — помилка.

## Якщо виникла помилка

- **Configuration file not found:** створіть `config.toml` саме поруч із executable. Пошуку в інших папках немає.
- **HTTP 401/403:** перевірте логін, пароль, права й доступність Basic Auth на сервері. Прихований ввід потребує інтерактивної консолі.
- **Помилка мережі:** перевірте адресу, мережу/VPN і доступність сервера. Наявна локальна база залишається доступною.
- **Missing library file:** перевірте `[libraries]` та `Altium Symbol`/`Altium Footprint` у InvenTree. Програма не підставляє відсутні моделі.
- **Database error / lock / journal:** закрийте споживачів бази звичайним способом і дайте їм завершити транзакції або відновлення. Не видаляйте `-wal`, `-shm`, `-journal` для обходу перевірки. Покинутий `.sync.lock` видаляють вручну лише після підтвердження, що його процес і всі sync до цієї бази зупинені; подробиці — в [архітектурі](../docs/architecture/inventree-sync-design.md).

Коди завершення: `0` — успіх, `1` — внутрішня помилка, `2` — конфігурація/дані/ввід, `3` — API/авторизація, `4` — база/файли/блокування. Інструкції для розробника: [inventree-sync/README.md](inventree-sync/README.md).
